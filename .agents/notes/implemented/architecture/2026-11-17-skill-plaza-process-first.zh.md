# Agent Note: 以流程为主的技能广场

Status: implemented

[English](2026-11-17-skill-plaza-process-first.md) | 中文

## 问题

广场已经存储并渲染执行内容，但读起来仍像一条数据库记录：目录是文字卡片，详情页把内容拆成三个标签页，流程图只是其中之一。没有手写流程的版本退回编号列表，于是这个本该解释「技能做什么」的界面可能失去它唯一的图。页面也没有表达「一个已发布技能是一份可复用的包，正文、示例与工具同属一体」。

## 决策

**详情页是一份文档，流程是它的主视图。** 结果示例、适用场景、流程与已存储正文是同一滚动页面的小节，用一行锚点而不是标签页切换。流程画布占满内容宽度，节点检查器就在旁边；选中节点仍然展示该步的用途、输入、检查、产出、验证与失败处理。

**没有流程的版本由步骤成图。** `flow-model.ts` 把有序步骤转换成与手写流程相同的平铺层形态，并把结果标记为派生，视图会说明它的来源。派生流程图仅用于展示：它从不被存储、发布，也不被模型可见正文的渲染器读取，因此执行正文仍是唯一的模型输入。

**目录条目携带读取时派生的流程预览。** `PlazaSkillEntry.flow` 保存活动版本根层最多四个缩短标签（没有流程时取自步骤），以及判断节点数量。目录在同一次存储域读取里通过活动版本记录映射每个条目，因此卡片能画出流程，而不需要每张卡片各发一次详情请求。发布返回的条目不带预览，因为广场在那里用不到它。

**详情读取返回已存储正文。** `PlazaDetailValue.body` 是发布时 `renderSkillBody` 写下的精确文本；技能包小节直接渲染它，而不是在客户端重新推导正文。草稿预览没有正文，因此隐藏该小节，预览不会声称自己拥有一个尚未发布的正文。

**只有在目录里存在多个技能时，才把最近更新的一个作为推荐位。** 只有一个技能的工作区保留普通网格，这样那张卡片自己的封面与操作仍然触手可及，而不是把唯一的条目提升成横幅。

## 验证

`pnpm exec vitest run packages/client/ui-skill-plaza/tests packages/skill/skill-plaza/tests` 覆盖：目录条目携带按步骤派生的预览、`detail` 返回已存储正文、带提示的派生流程视图、单页上的节点选中与子流程返回、推荐位「先钉住再使用」的路径，以及包含自环的流程计数。Web e2e 规格在预置 Host 上驱动构建后的客户端，拍摄目录、详情、节点与窄屏截图，并断言装配后的页面出现流程提示与结果图。

## 备选方案

**为每张卡片读取详情来画缩略图** — 否决：在一个已经读取目录的页面上每张卡片各发一次请求，而且卡片会展示目录本身无法描述的流程。

**在客户端从内容重建 `SKILL.md`** — 否决：这会重复 `renderSkillBody`，并让预览与模型实际读到的内容发生漂移。

**保留标签页，把流程图加进概览** — 否决：同一个流程会有两处描述，而标签顺序仍然决定读者是否会看到它。

## 后果

目录读取现在还会从同一存储域取出每个活动版本记录；条目多出一个可选字段，详情值多出已存储正文。较早发布、没有手写流程的版本照常工作：它像每个版本一样存有正文，并在目录第一次列出它时获得一张派生流程图。
