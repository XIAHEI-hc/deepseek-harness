# Agent Note: 技能广场的展示内容、工作区媒体与持久钉住

Status: implemented

[English](2026-11-16-skill-plaza-display-content.md) | 中文

## 问题

技能广场此前只存执行正文：已发布版本带标题、用途、有序步骤和验证文字，因此广场能列出并调用技能，却无法说明它的结果长什么样、流程如何分支、调用方该试什么。产品需要的概览、执行流程与使用说明三个界面没有可读的数据来源，而且有两处行为对该产品不安全：详情页无法读取某个精确的已发布版本；钉住的版本只存在 Host 内存里，因此选择版本与发送任务之间重启 Host，会静默运行当时的当前版本。

另有两种数据形态本身就不可行。嵌套的 `subflow` 对象是递归类型，而 Typert 的 Remote 编解码器在生成产物时拒绝未命名的递归载荷。把图片存成存储域之外的文件，则会引入第二套介质，而它与草稿、版本之间的一致性无人负责。

## 决策

**版本在执字段之外携带可选的 `presentation` 内容。** `PlazaDraftContent` 保留 `title` 到 `toolDependencies` 作为模型可见正文，并新增 `schemaVersion`、`category`、`scenarios`、`examplePrompt`、`coverAssetId`、`examples` 与 `workflow`。`renderSkillBody` 从不读取 `presentation`，因此展示内容不会意外变成模型指令；编辑器也明确写出流程图与步骤是两份独立内容。

**流程图是一组平铺的层加一个根层标识。** 每层持有节点与边；节点通过 `subflowLayerId` 指明它打开的层。这样既能表达分支、汇合和嵌套子流程，又保持非递归的 wire 类型，并把嵌套限制在三层。选择平铺而不是手写「嵌套转平铺」的转换器，是因为存储、wire 与编辑器共用一种形态，使带位置校验路径、编辑器和流程视图读的是同一份东西。

**发布校验放在做出该决定的操作里。** `publish` 会按发布工作区的媒体检查整份展示载荷，并以第一条定位到的问题拒绝：重复节点标识、缺失入口节点、断链、不可达节点与层、判断分支缺标签、无法解析的资源，以及尺寸上限。`check` 不写入就返回同一批问题，供编辑器标出；发布与否从不由前端决定。

**图片是同一存储域内的不可变工作区记录。** 上传按文件签名判定，而不是按文件名或声明的媒体类型；一张图片以其工作区内的不可变资源标识只存一次，已发布版本引用这些标识。因此替换草稿里的图片不会改变旧版本显示的内容。版本的展示快照与执行正文一起写入，恢复介质即恢复两者。

**版本绑定持久化并校验工作区。** `pin` 写入 `pins` 表，而不是 Host 本地映射；pre-step 处理器在注入前会丢弃工作区已不匹配的绑定。因此在选择版本与发送任务之间重启，仍会注入该版本；在一个工作区做的绑定也不会注入到另一个工作区的会话。

## 验证

Host 规范覆盖：展示内容经保存、发布到详情读取的往返；阻塞发布的定位问题与通过检查的干净载荷；每种可接受格式的媒体准入、字节与像素上限以及工作区读取过滤；旧版本内容在新版本发布后保持不变；以及同一介质的新读取者能读到钉住记录。Client 规范覆盖：目录筛选、按精确版本读取详情、节点选中及其子流程往返、无流程时回退到步骤、编辑器的保存、被阻塞的发布、冲突面板与预览，以及页面 face 上「先钉住再插入」的路径。`verify-client-ui-i18n` 覆盖新增文案，聚合 typecheck 覆盖扩展后的契约。

## 备选方案

**把展示内容排除在版本快照之外** —— 否决：发布后编辑草稿会改变旧详情页显示的内容，版本就不再不可变。

**把媒体存成域旁的文件** —— 目前否决：它会引入一套与版本快照一致性无人负责的介质，而域内的读取过滤已提供工作区隔离。代价记录在「已知限制」里：一张图片会在域文档中占下其编码后的体积。

**从步骤推导流程图** —— 否决：从散文里猜分支标签与检查项，会把展示结构带进模型路径，并让每次步骤编辑悄悄重写流程图。

## 影响

所有发布界面现在都必须满足展示内容校验，包括早期版本写入的草稿——它们缺失的 `presentation` 会原样接受。版本的展示内容与图片在介质存活期间都可读；没有任何操作会删除已上传图片，这让旧版本保持完整，代价是被弃用的图片会被保留。详情读取、媒体读取与钉住都先解析工作区，因此不传会话的调用方始终指向 Host 默认目录。
