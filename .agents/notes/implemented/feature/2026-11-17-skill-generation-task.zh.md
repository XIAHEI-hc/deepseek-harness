# Agent Note: 技能生成是一次看得见的任务

Status: implemented

[English](2026-11-17-skill-generation-task.md) | 中文

## Problem

完成回复上的生成入口是一次发出去就不管的 Remote 调用。`skillPlaza/generate` 在请求里跑完整条模型调用，调用方只看到几十秒的禁用按钮，成功时整块主面板被草稿编辑器替换。用户分不清生成是慢还是坏了，也没法中途停下；成功的那一刻，正在读的那条回复也消失了。

## Decision

**`generate` 立即作答，尝试自己携带进度。** Host 先记录这次尝试，把模型调用放到它后面运行，然后返回该记录。运行期间 `job` 报告尝试到达的阶段（`harvest`、`distill`、`check`、`save`）以及模型已产生的字数；`cancel` 中止那次模型调用并把尝试落定为 `cancelled`。重复请求加入仍在运行的那次尝试，失败或已取消之后的请求运行同一任务的下一次尝试。由于一次尝试就是一份 JSON 文档，进度写入被限制在每 400 毫秒一次。

**客户端跟随耐久记录，而不是握着一个 promise。** 每个轮次一个任务，镜像进按会话划分的生成状态存储，以该轮收尾消息标识为键；尝试运行期间客户端轮询 `job`。跟随记录而不是挂起的 RPC，才让第二次点击、重试与取消都作用在同一次尝试上。

**任务卡位于操作行之上，而不是新开一个区域。** 它渲染在 `conversation.chat.turnTail`，其属主输入新增了收尾消息标识，卡片因此锚定在产出它的那条回复上。四个状态就是全部界面：进行中（阶段清单、已产生字数、用时、取消）、已生成（标题、用途、标签，以及唯一一个打开草稿的操作）、失败与已取消（可读原因加重试）。

**生成完成不跳转任何页面。** 进入广场是结果卡或入口上的显式操作。入口本身也带耐久状态：已经产出过草稿的轮次显示「已生成 · 查看」，而不是再提供一次生成。

## Testing

`packages/skill/skill-plaza/tests` 在真实存储上驱动真实服务：并发加入、失败后重试、阶段与字数报告、取消运行中的模型调用、迟到的取消不影响已落定的尝试，以及未知的尝试标识。`packages/client/ui-skill-plaza/tests` 覆盖入口的四种文案、卡片的阶段与结果、取消与重试接线，以及两个入口共享的那个存储。

## Alternatives considered

**用流式 Remote（`@Remote({ mode: 'stream' })`）代替轮询。** 流可以不用定时器就推送进度，但它需要广场本来不用的传输方式，会随标签页断开，也无法回答一个重载后的页面。轮询读取的是 Host 本来就在写的耐久记录，因此无论何时接入，调用方看到的都是同一次尝试。

**尝试落定时直接跳进广场。** 原行为让结果不可能被错过，也不可能被拒绝：对话消失，编辑器无论用户是否想要都会出现。改为按需打开后，结果仍是一次点击之遥，而回复留在屏幕上。

**用客户端定时器编一份阶段时间表。** 假进度不需要任何 Host 改动，代价是告诉用户一个 Host 并未确认的故事。卡片报告 Host 到达的阶段，没有阶段时就不显示阶段。

**把卡片渲染成会话节点。** 节点能随重放恢复，但生成是一项素材从不进入会话模型输入的旁路任务；为它写会话事件会把界面状态塞进转录。广场的尝试与草稿记录才是耐久事实，卡片只是它们的视图。

## Consequences

等待变得可读、可停、可重试，做技能的过程里回复一直留在屏幕上。代价是「轮次对应哪次尝试」的映射活在浏览器里：重载之后卡片消失而草稿仍在，再次启动会加入 Host 上仍在运行的那次尝试。进行中的卡片报告阶段与字数，而不是草稿字段，因为 Host 不发布局部内容。每个运行中的尝试每 700 毫秒花一次很小的 `job` 读取。

## What this record does not claim

生成仍然没有持久队列：模型调用活在 Host 进程里，尝试期间重启会丢掉它，而记录会保留最后到达的阶段。同一个轮次里并行两次生成不受支持；入口与卡片都只寻址每个消息标识下的一次尝试。
